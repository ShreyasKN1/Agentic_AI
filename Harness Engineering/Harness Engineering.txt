=> State Management
State management is how the harness tracks the current condition and progress of an agent execution.
Context is what the model sees, state is what the system knows about the execution.
State can contain:

->objective
->current task
->current iteration
->tool calls made
->files modified
->tests passed/failed
->errors encountered
->agent status
->budget remaining
->checkpoint

Example:
AgentState {
    objective;
    currentTask;
    iteration;
    filesChanged;
    testResults;
    errors;
    toolHistory;
    status;
}
State allows the harness to answer:
Where are we?
What already happened?
What failed?
What should happen next?


Flow:
User Objective->Create Agent State->objective, current task, iteration, tool history, test results, errors->Model->Tool Call->Tool Result->Update State->Continue / Stop

=>Tool Contracts & Result Normalization
A tool contract defines exactly what a model is allowed to call and what input/output format the harness expects.
Result normalization converts messy tool output into structured information useful to the model.

A tool should define:

Tool name
Purpose
Input schema
Output schema
Permissions
Timeout
Error behavior

Example:

runMaven()
Input:
{
    command: "test"
}
Output:
{
    status: "FAILED",
    exitCode: 1,
    failedTests: [...],
    errors: [...]
}

Instead of giving the model 50,000 lines of Maven output:

Maven->50,000 lines then harness parses our output->faiures errors extracted and then structured output->model.
This makes tool interaction predictable.

Flowchart
Model->Tool Request->Validate Tool Contract->Check Input
->Execute Tool
->Raw Result
->Normalize / Parse
->Structured Result
->Model

Human-in-the-Loop
Human-in-the-loop means the harness decides that certain actions require human approval before execution.
The model can propose an action, but the harness controls whether that action can happen automatically.

Low-risk actions:

readFile()
searchCode()
runTests()

can be automatic.

Higher-risk actions:
git push
production deployment
database migration
delete files
access sensitive data
can require approval.

The important concept is:

Autonomy is a policy decision made by the harness.

Flow:
Model->
Tool Request->
Policy Check-> Low Risk or High Risk -> high risk means Human Approval->Allow to execute or reject
                if low risk-> execute

Progress Detection: the agent is actually moving toward the objective or repeatedly performing ineffective actions and repeating the same again and again.

imagine performing a task-> iteration1-> 10 test failures
 iteration2->same 10 test failures
 iteration3-> same 10 test failures
 iteration4->same  10 test failures
harness detctes No measurable progress

we need to make sure error changes, fewer errors caught, new evidence detected and tool successfully executing.

flow:
agent action-> observe result-> measure progress-> yes or no -> yes means continue otherwise check for stagnation -> retry/replan -> stop

Very important topic here even used in rag based system or any ai system called checkpoints and rollbacks,
Checkpointing saves a known state before risky agent modifications.
Rollback restores that state when the agent produces a bad result.
For coding agents, Git is commonly useful for this.


A checkpoint can be either,
Git commit
Git branch
filesystem snapshot
container snapshot
database snapshot
 now, flow here is simple:
known good state-> add checkpoint->agent changes something-> run tests and check if result is good or bad->yes now this back new known good state-> again we continue here
											 if bad -> rollback->previous state

=>Failure Taxonomy
A harness should distinguish why an agent failed instead of treating every failure as simply "model failed."

Identify failures:
Reasoning failure means model misunderstood the problem

Context failure means req information wasn't available

Tool failure/Tool itself failed

Environment failure being JDK/Maven/network/container problem

Policy failure from org, Requested action wasn't allowed

Execution failure->Generated code was incorrect->retry/replan

Verification failure->System couldn't establish success-> fix would be to fix code

Loop failure->Agent repeatedly performed ineffective actions-> stop/replan

flow:
identify failures-> fix them accordingly-> 1st fix->replan,2nd fix->retry tool,3rd fix-> environment change,4th fix is reject.

=>Budget Management:
Budget management limits how many resources an agent can consume during execution.
Without budgets, an agent can potentially continue indefinitely.

An agenet harness should enforce,
Maximum iterations
Maximum tool calls
Maximum tokens
Maximum execution time
Maximum CPU
Maximum memory
Maximum API cost


flow: before every action-> check budget allowed-> yes means continue and update budget no means stop
